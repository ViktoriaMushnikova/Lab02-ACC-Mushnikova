В Debug есть конструкции nop, блок .locals init и операции с локальными переменными, а также переход br.s.
В Release компилятор убрал лишние локальные переменные и промежуточные инструкции. Количество IL-инструкций в методе Add() изменилось с 10 до 4.


## Контрольные вопросы.

# 1. Что такое IL и зачем он нужен между C# и машинным кодом?
IL - это промежуточный код, в который компилируется C##. Он нужен для переносимости: сборка не привязана сразу к конкретному железу, а JIT-компилятор при запуске переводит IL в машинный код под систему.

# 2. Почему .dll можно декомпилировать? 
В NET-.dil вместе с IL лежат метаданные с именами классов, методов и типов. По ним и IL декомпилятор вроде ILSpy легко восстанавливает код.

# 3. Какие отличия Debug и Release вы увидели в IL? 
В Debug есть nop, .locals init, лишние переходы. В Release компилятор убирает лишнее, поэтому в Add() стало 4 конструкции вместо 10.
 
# 4. Почему Release обычно быстрее Debug? 
В Release включены оптимизации и нет отладочных вставок, поэтому меньше лишних операций и обращений к памяти.

# 5. Почему строковый пароль в .dll нельзя считать защищённым?
Строка остаётся в сборке и видна при декомпиляции или просмотре IL-строк файла.
